# 机械臂构型选择

## Purpose

从任务需求形成可追溯、带条件的构型候选。面向自研机械臂方案设计，使用按任务和构型组织的统一参考资料；区分原始证据与工程推理，不把案例当设计验收。

## When to use

- 根据场景选择机械臂自由度、几何、肘腕、驱动或部署组合。
- 比较已有构型，或核对用户指定构型与任务是否冲突。
- 为后续参数设计列出输入和验证计划。

单纯计算关节扭矩、生成模型或运行仿真时，转到相应任务；本技能只在需要构型判断时介入。

## Inputs

接受自然语言、任务表或已有设计。先辨认任务及必须动作、载荷与工具、目标位置/姿态、运动范围和部署条件；其余缺项保持“未知”。完整字段见[输入输出约定](references/decision-contract.md)。场景初选不要求用户先提供完整DH参数。

## Workflow

### Step 1 确认需求

把已有信息整理成需求清单，分硬约束、偏好、未知项并保留单位及坐标系。先列接近、操作、退出的工具位置/姿态，再判断任务维数；不要只按行业名称选轴数。若关键缺项会改变选择，集中询问这些事项，同时继续说明已有依据的方向。不要把资料中的3kg、600mm或7轴当默认输入。

### Step 2 读取相关证据

先读[知识库入口](references/knowledge-index.md)，根据任务读取相关专题；所有资料参与同一选择流程，不按来源设定模式。纯文本缺资料时按末节降级。

| 当前问题 | 按需读取 |
| --- | --- |
| 场景、任务维数及1/2/3/4/5/6/7轴初筛 | [任务与自由度](references/task-dof-selection.md)、[场景表](references/scene-index.md) |
| 龙门、圆柱/球坐标、SCARA、码垛、串联、Delta、平台、绳索、连续体、RCM | [构型总表](references/arm-layouts.md) |
| SRS/偏置、腕、驱动、感知及部署取舍 | [设计取舍](references/design-tradeoffs.md)；细节再读[整臂](references/arm-layouts.md)、[驱动](references/drive-layouts.md)、[肘腕](references/joint-mechanisms.md)、[专用机构](references/special-mechanisms.md)、[部署](references/deployment.md) |
| 排除判断、已有方案复核 | [验证清单](references/verification-checklist.md)、[证据边界](references/evidence-boundaries.md) |
| E/G编号、事实与推理的支持范围 | [来源登记](references/source-index.md)；需要案例参数时定位[案例与专项分析](references/case-studies.md)对应章节 |

不要一次加载全库。新增外部资料或当前商品规格需要另行核对并记录日期；包内原理和摘要可离线使用，遵循宿主的联网与工具要求。

### Step 3 组成候选

每个候选分别写明：机构族、真实自由度及轴线/支链关系、肘腕或末端机构、驱动与电机位置、感知/控制、部署。未知项仍写未知。不同维度可以组合，例如7轴与准直驱不互斥。保留用户已指定的设计，不擅自改成默认串联臂。

### Step 4 核对约束并比较

逐条对照需求，记录“有证据符合／明确冲突／未知／不适用”。证据必须适用于当前对象与工况。参考样机的性能不证明新臂性能；单一样机不足不证明整类机构不可能。

为候选选择状态：candidate为列入比较，conditional为条件候选，excluded为明确冲突，insufficient_evidence为证据不足。状态都不表示工程验收通过。候选数量随证据决定，不凑数量、不编造总分。

### Step 5 输出并复核

使用下方Output format。交付前确认：每项实质取舍区分事实/推理且有来源、用户约束未被替换、未知未填默认、排除范围未泛化、待验证未写成通过。需要继续计算或建模时读取[分析衔接](references/analysis-handoff.md)，确认数据和工具范围后再执行。

## Output format

默认输出四部分，简短任务可合并呈现：

1. **需求与未知项**：用户确认的任务与运动维数、硬约束、偏好和缺项。
2. **候选比较表**：候选及状态、完整构型、优势、代价/冲突、来源与范围、待验证项。
3. **选择结论**：优先方向及条件，或说明目前不能区分；不宣称唯一最优。
4. **下一步**：最关键的补充信息和验证任务；没有运行的检查写待验证。

文件报告使用[报告模板](assets/selection-report.md)，按任务删减无关栏，不输出未填写的模板文字。机器交接的JSON字段见[输入输出约定](references/decision-contract.md)，不要将选择记录直接传给模型生成器。

## Rules

- 来源只支持明确覆盖的对象。A—I及J系列为报告/附件，E01—E21为教材/研究/官方资料，G01—G08为工程推理；引用写“编号＋位置＋支持内容”，推理另写假设与待验证项。
- 区分商品、项目设计、研究样机、专利、用户输入和实际计算；不混淆载荷与工具、分辨率与精度、采样频率与带宽。
- 7轴不等于SRS，单轴限位不等于联合姿态域，位置可达不等于无碰撞或带载可执行。
- 直接使用统一参考资料；不凭未登记的模型记忆补规格或宣称已查来源。资料冲突并列范围，不挑选有利数据。
- 并联、柔性和连续体不直接当作串联刚体链验收，等效模型必须注明忽略项。

## Examples

- 输入“家用机械臂，给唯一最优”：先补关键需求，不默认7轴；可先给条件分支。
- 输入“腕两轴±90°，比较本项目并联腕”：核对B第3章，排除照搬不满足范围的具体设计，不否定所有并联腕。

完整任务示例见[示例](references/examples.md)。示例参数仅属于示例。

## Resource loading and fallback

核心内容是本文件、references和报告模板，不依赖Codex API、特定模型、Python、Node、联网或原始挂载盘。agents/openai.yaml仅是可忽略的Codex界面元数据。

有文件读取能力时按Step 2取资料；每阶段保留需求、已读来源、候选状态和待办，读取失败先说明受影响结论，不能假称已核对。上下文较小时一次处理一个专题，保留需求及候选编号后再比较。只有文本输入能力时，由调用方提供本文件和相关参考正文；资料未提供就说明无法核对，只输出需求清单或证据不足的候选，不假称已读取文件。

完整审阅见[综合对照表](references/selection-tables.md)，具体参数见[案例](references/case-studies.md)，追溯见[来源登记](references/source-index.md)。按需读取，不要求每次加载全集。
