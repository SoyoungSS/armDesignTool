# 面向通用场景载荷谱的模型交接

生成器准备机械臂本体，不预先绑定分拣、工具或任务阶段。质量/COM/惯量、驱动与碰撞表面必须对应预期分析目的；视觉模型能加载不等于接触与载荷可信。

## 新增产物

`report/load_handoff.json` 随 manifest 哈希清单保存，包含全部原始关节的 parent/child/type/origin/axis、活动关节名单、fixed 连接名单、驱动与 SI 单位、安装、初始 keyframe、tool_frame，以及测量定义。manifest 的 load_handoff 给出相对路径；交接整个 run，不能仅复制 JSON。

MJCF 每个原始关节的 child 原点添加 child-attached site 与 force/torque sensor：

- `load_site_<joint>`：child 系原点、单位姿态；不会增加质量或约束。
- `load_force_<joint>`、`load_torque_<joint>`：三维力/力矩，传感器计算使用 MuJoCo 的子体朝父体约定。
- 固定连接保留 body 与测点，记录接口六维载荷，但不生成虚假 DOF、关节速度或驱动力矩。

传感器标识与 body/关节名称分别映射，不依赖前N个 qpos、nv 或执行器。URDF/ROS1/USD 不会因此宣称拥有可运行的 MuJoCo 力传感器；只有实际生成 MJCF 时 section_sensors_generated 为 true。生成但未运行时依然保留 runtime_validation=pending。

静态检查核对每个连接的 site、位置与力/力矩传感器配对；场景运行器再核对编译后的 body 拓扑、测点方向、传感器类型/维数及主动关节覆盖。旧模型无此文件时维持原验证流程，不能声称已经有六维接口输出。

## 模型可信度与资产诊断

载荷谱需要每个运动体的真实或显式估算质量、COM、正定且物理合理的惯量、驱动类型与限制、安装及工具/载荷归属。handoff 保留 model_grade 与 missing_physics；估算模型只能得条件性载荷，不升级为实机证据。新加工具或工件不可重复计入已有下游质量。

借鉴 robotics-antigravity-plugin/mujoco-audit 的按资产用途诊断方式，在任务项目中为相关资产选择必要测试：

| 对象 | 诊断与证据 |
|---|---|
| 工件/夹指 | 接触几何与视觉对齐、静止/抬升/滑移、夹持力与摩擦敏感性 |
| 容器/孔/通道 | 空腔与开口真实存在，探针或目标物通过，不用单凸实体封死空腔 |
| 薄壁/高速接触 | 时间步减半、穿透/接触峰值对比，不能只验证 XML 可编译 |
| 机械臂本体 | 已有装配、惯量、碰撞面复核、初始姿态与有限轨迹验收 |

以上为按需执行的诊断计划，尚未提供统一的资产十场景自动测试 CLI；不把跌落/堆叠测试强加给固定整臂。记录实际执行的测试、阈值来源与不适用项。

六维值是理想刚体树切面在指定参考点的接口 wrench，不直接等于轴承分担、丝杠支链力或结构应力。并联/闭链/柔性与传动拓扑仍需要专门建模。传感器不弥补此类拓扑能力缺失。
