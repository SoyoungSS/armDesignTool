# 机械臂任务仿真与载荷导出

输入是**模型生成器的一次实际输出**和**用户希望机械臂完成的任务描述**，不是模型生成器的源码目录。本 skill 是 agent 工作流程与通用工具包；agent 需要根据任务编写场景生成器、感知/规划/控制适配器，不存在一个自动理解所有任务的固定控制器。

## 入口与确认

先读 [输入与确认契约](references/intake.md)，只读检查上游输出。已有用户答复可以复用，不能反复询问，也不能将其他任务的选择沿用到本次。

在任务信息不完整时，整理具体缺项、可选方案及其影响向用户确认。**没有答复就是未确认**，不得用默认数字、示例工况或所谓合理假设代替答复。可以继续只读检查、整理资产和准备草案，但不能执行依赖这些缺项的正式仿真。

必须确认本次仿真方式（官方 WebViewer 或本地原生窗口；批量无窗口验证须说明）、任务目标/成功标准、策略、环境与工具/载荷参数、初始和终止条件、每轮定义、轮数、轮间是否复位/重采样、节拍/速度/停留、输出位置及数据需求。若用户明确委托选择某项，可提出具体方案并记录授权范围，仍需确认轮数和仿真方式。

将用户原文、答复、上游继承的参数、批准的估算及未解决问题保存为 `task_contract.json`。以 [assets/task_contract.template.json](assets/task_contract.template.json) 为起点；模板故意未批准，不能直接运行。`scripts/contracts.py` 检查必需字段，无法替代 agent 对用户真实答复的核对。

## 执行链

1. **模型接入。** 阅读上游 manifest、normalized_model、drive_design、validation、初始 keyframe。用 `scripts/inspect_generator.py` 检查路径和清单哈希；缺失、失败、版本不符或旧入口冲突先处理。只复制到任务工作区，禁止改上游模型或其他 skill。保留关节名称、安装坐标、惯量来源、驱动和初始滤波状态。
2. **理解任务与资产。** 按 [场景与策略](references/scene-strategy.md) 提取对象、工具、支撑、障碍、传感器及交互。建立资产清单，生成/导入合适的 MJCF、mesh、纹理；确认尺寸、质量、惯量、摩擦、材料和可动性。把视觉、碰撞、动力学与任务状态分开，逐项记录来源。机械臂只有法兰时不能假定已有夹爪。
3. **策略实现。** 用户明确指定视觉伺服、检测后抓取、仿真真值位姿等策略时严格落实并保留证据。未指定时提出规划方案供确认，优先任务状态机、IK、无碰撞路径、时间参数化和有界反馈控制。不能把读取真值伪装成视觉识别，也不能把刚性焊接搬运伪装成摩擦抓取。
4. **安装与运行。** 按用户选定模式读取 [安装与官方接口](references/install-api.md)，探测 OS、Python、MuJoCo、渲染与可用设备，选择兼容环境，记录实际版本。必要的环境安装放到任务工作区。两种查看模式共用同一任务控制和采样链路；官方 WebViewer 仍有本地物理后端。不能擅自替换为自制图片流或纯回放。
5. **小段验证。** 检查场景资源、质量、关节/执行器映射、初始状态、接触、控制限幅、轨迹可达性和失败处理。碰撞、失稳、掉落、任务失败时保存证据；按已确认参数修复并试跑。涉及任务目标/物理假设变更要再确认。见 [验证与交付](references/validation.md)。
6. **正式执行。** 按确认轮次运行完整动作，涵盖接近、操作、释放/退出、返回、停留等阶段。数据采样按物理时钟，不按渲染帧。实时窗口的暂停/继续必须真正控制物理步进。重新开始建立新 run，不能倒退时间后追加进同一时序文件。
7. **导出。** 遵守 [数据和目录规范](references/outputs.md)，记录关节位置/速度/加速度/驱动扭矩（移动轴为力）、末端位姿/线角速度/线角加速度，并保留接触、控制输入、约束载荷、功率、轮次和任务事件。生成 CSV、曲线、统计和结果文档，交付实际 run 路径。

## 通用工具

所有命令中的 `<skill>`、`<project>` 为占位路径，调用时替换成实际绝对路径；不依赖 Codex 工具或 Windows 用户名。

```text
python <skill>/scripts/inspect_generator.py <generator-output-or-run> --out <project>/model_inspection.json
python <skill>/scripts/contracts.py <project>/task_contract.json
python <skill>/scripts/run_task.py --project <project>
python <skill>/scripts/analyze.py <project>/runs/<run-id>
```

`run_task.py` 是通用记录和运行框架，要求 agent 实现约定的任务适配器；读 [适配器接口](references/adapter.md)。默认记录器支持上游固定基座串联 hinge/slide 轴，可以同时存在工具、夹爪和带 freejoint 的物体；不会把物体自由度误认为机械臂关节。机器人自身的球/自由关节、闭链、柔性或自定义积分器需要扩展记录器并验证后使用。

规划器和任务资产不能被硬编码成七轴擦白板。需要更复杂的规划/视觉库时先说明用途和安装规模，按已确认策略选用，不强制引入 ROS、训练框架或 Node。

## 解释边界

完整保留真实时序、正负载荷、循环/停留和失败试验，供后续载荷谱、寿命与驱动设计使用。没有传动效率、减速比、疲劳曲线、材料与应力映射，就不能把关节驱动扭矩直接换算成电机轴载荷或寿命。关节反力、驱动力、末端接触力、轴承载荷是不同量，不能互相替代；缺少的派生量在报告中明确标记。

本包不要求个人目录安装。其他 agent 读取标准 `SKILL.md` 与相对引用即可；`agents/openai.yaml` 只是可忽略的界面元数据。运行产物默认放到用户指定的任务目录，而不是写回 skill。
