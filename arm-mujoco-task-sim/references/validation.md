# 验证与完成标准

先做有代表性的短试验，再做用户确认的完整轮次。不能为完成例程额外猜测一套任务运行；本 skill 制作中的测试夹具仅验证工具，不代表用户任务成功。

## 输入与模型

- 生成器本次尝试、入口、include/mesh 依赖、hash、质量来源、初始 keyframe。
- SI 单位、基座安装、TCP、qpos/dof/actuator 映射。机器人与自由物体、夹爪的 DOF 分开。
- 新增物体惯量正定、质量合理、碰撞参与正确；工具质量没有重复计入。

## 控制与物理

- 初始/全程状态有限，无不稳定警告、越限或不合理瞬移。
- 检查 actual effort、ctrl 与 actuator_force，区分控制饱和与驱动输出饱和；位置伺服输入到限位不等于电机扭矩饱和。
- 实际速度/加速度/力矩与已知能力比较；无法获取能力时标为未验证，不自动填通过。
- 所有预期接触都有任务含义；意外穿透、非目标碰撞、抓物滑落有证据。
- 接触或峰值关键工况作时间步减半/求解设置敏感性检查，报告绝对及相对差异；阈值结合用户用途，不能凭固定数宣称可信。
- 用有限差分检查一段光滑运动中的速度/加速度趋势，注意采样时间对齐与接触切换；不要在复位/碰撞时强制套光滑导数假设。

## 任务与可视化

- 抓放：抓稳、保持、到达容差、释放后稳定，禁止只判断 TCP 到了目标。
- 擦拭：实际接触力/覆盖/扫过后的擦除，禁止只按时间删除字迹。
- 视觉：识别/视觉误差、图像时间、失败处理、无真值泄漏到指定视觉控制链。
- 实际轮数、成功/失败/重试与确认定义一致，超时是失败/未完成。
- 官方 WebViewer/NativeViewer 实际显示场景，时间/机器人随物理推进，暂停/继续有效。各系统未测的部分明确“按官方文档提供安装方法，未在该平台验收”。

## 交付判断

数据、图、报告、代码和环境可定位；失败运行也可追溯；报告区分已验证、未验证和简化假设。文件不为空并不代表成功。限制条件不满足时交付诊断/部分结果，并说明需要用户确认或补充的具体事项。

工具包自测：`python scripts/self_test.py --output <新建测试目录>`。测试混合旋转/移动关节、场景 freejoint 地址隔离、TCP 向心加速度、未确认合同拒绝、完整多轮数据和导出。测试结束后另核实目标上游包可以通过完整性检查与编译。测试目录应在本次允许写入的位置，不改其他 skill。
