# 默认概念试算：先生成可用载荷谱，再通过描述迭代

## 模式与授权

用户要求前期设计、常规用法、先试跑、自动补齐或辅助载荷谱时，采用 `assumption_policy="concept"`。普通场景请求也默认概念试算；明确要求精确参数、验收或逐项确认时用 `strict`。网页“开始场景仿真”授权 Agent 按本节补齐缺项并直接运行，无需再等用户确认一份方案。

这是对估算范围的委托，不是对每个估算数值的用户确认。`confirmation.evidence` 保留原请求/点击来源及授权策略；在合同写 `assumption_authorization` 和 `assumptions`，逐项记录实际用值、来源、用途和可修改项。用户给出的明确约束始终优先，已有模型质量、负载、驱动和工具不得重复添加或擅自改动。

## 缺项处理顺序

1. 先从已选完整模型、当前描述、上次任务记录提取已有值；“负载改成 1 kg”“速度减半”作用于上一场景，保留未修改内容。
2. 剩余缺项使用下表作为可调整的概念起点，Agent 需把最终采用的具体值写入资产、策略、合同和结果。它们不是材料标准、硬件能力或已证实工况。
3. 一般缺项记为假设和建议改进项，不放入阻塞的 `unresolved`/`blocking_issues`。只有模型文件缺失、无法编译、真实驱动/惯量缺项导致无法物理步进、拓扑不支持或明确约束无法满足时，才停止并给出具体原因。

| 缺项 | 概念起点与边界 |
|---|---|
| 轮数 | 1 个有定义的作业循环；不自动套分拣三轮 |
| 节拍/试算时长 | 代表性运动周期从 5 s 起，末尾稳定约 1 s，最大试算时间默认 10 s；按行程和已有限速调整周期或减小幅度，遵守服务器上限 |
| 运动范围 | 优先描述的作业区域；只知一般动作时，在有效限位内选择不超过可用行程 10% 的往返，采用平滑插值和碰撞检查 |
| 速度/加速度 | 优先已有驱动限制，未知时低速起步；旋转速度起点不高于 min(已有速度限制的25%, 0.3 rad/s)，移动速度不高于 min(已有限制的25%, 0.05 m/s)。不把这些起点当硬件额定值 |
| 初始姿态 | 优先生成器 initial keyframe。未明确要求该姿态且发生碰撞时，可在限位内寻找无碰撞的概念起点，记录变更；原始输出只读 |
| 控制/感知 | 沿用原驱动模式与限幅，采用最简单可行的平滑位置/有界反馈控制；普通试算允许仿真状态真值，明确记录，不冒充视觉算法 |
| 工具/物体 | 自由运动不添加虚构工件或夹具。搬运任务先沿用模型已有负载；确无负载信息而任务需要工件时，可用 0.1 kg、50×50×20 mm 方块作为概念占位，记录质量与惯量来源并避免重复计重 |
| 摩擦/接触 | 需要近似接触而未给材料时可用滑动摩擦系数 0.5 的概念占位；接触阈值按代理尺度、软接触和任务判据给明确估算依据，不称为实测材料性质 |
| 工具机构不可用 | 优先理想夹持、等效末端载荷或其他代表性载荷代理；`simulation_scope="load_proxy"`，明确未验证真实抓稳/擦拭/插入，而不是无限索要夹爪图纸 |
| 判据/随机性 | 依据任务给出可测量的位置、速度、接触或保持判据；位置起点可用 0.02 rad/1 mm，具体值写入合同并自检；默认不随机，seed=42 用于复现 |

不能为“先成功”删除应有碰撞、越过驱动限制、伪造惯量、直接覆写物理状态或将达到最大时长当成功。代理也必须在 MuJoCo 中真实步进，记录实际广义力和接口载荷。无法表达真实接触时，交付明确标记的载荷代理而不是伪造原任务成功。

## 输出与恢复

- 结果标明 `concept`，区分 `task` 和 `load_proxy`；用户已知输入、Agent 假设、真实计算分别保留。
- `missing_inputs` 中的一般补充建议移入 `follow_up_questions`；模型/执行能力问题单列 `blocking_issues`。
- `task` 的成功仅指所列概念参数下的任务；`load_proxy` 的成功仅指代理载荷工况，不宣称原始抓放/插装等已验证。
- 场景准备或预检失败时，网页可把真实诊断反馈给 Agent，自动修复一次；只可调整被委托的假设、场景文件或未明确指定的初始姿态。保留所有诊断，不修改原模型、不降低碰撞规则。仍失败就停止。
- 正式物理运行的失败/中止不被重试掩盖，已记录载荷仍导出。用户修改描述后创建新的任务，保留上一任务及假设作为上下文。

严格模式继续要求关键参数完整、先审阅计划再运行，不使用上述数值替代用户确认。模板的 strict 字段用于兼容旧工程；概念任务应显式覆盖为 concept。
