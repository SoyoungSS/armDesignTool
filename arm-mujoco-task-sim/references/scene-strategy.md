# 从任务构建场景与策略

## 场景分解

逐项写入 `assets/manifest.json`：id、用途、来源（生成/用户提供/外部）、路径/hash、单位、视觉与碰撞表示、尺寸、可动性、质量/COM/惯量及来源、摩擦/接触参数、安装坐标、批准记录、资源许可证（外部资产）。资产数量由任务决定。

用基础几何即可满足物理目的时优先 MJCF primitives；复杂外观可生成 mesh，但碰撞用经验证的简化体/凸分解。图像纹理不是接触几何，视觉生成模型也不自动带有正确物理属性。动态物体使用惯量和自由关节，固定环境不可误赋移动自由度。薄板、抓取物和细小接触检查尺度、时间步和穿透。

抓放通常需要夹具、可抓物、支撑面、目标容器/区域，可能需要相机和光照；擦拭需要表面、工具、字迹状态；插装需要孔/销公差和接触柔顺；推压需要对象运动约束、接触目标及力限制。它们是提问线索，不是固定资产模板或用户未提供参数的默认值。

## 策略优先级

1. 执行用户指定方法，若不可用，解释具体缺项和候选替代，得到确认后再改。
2. 无指定方法：提出基于规划的方案。拆任务状态机，构造抓取/接触目标，求 IK，做碰撞检查和时间参数化，使用有界位置/阻抗/力反馈。用户确认策略与感知方式后执行。
3. 说明初始可达性、奇异位形、冗余分配、速度/加速度/力矩限幅、失联/未识别/滑落等失败转移。规划目标与实际到达状态分别记录。

## 感知与控制不能混淆

| 指定方法 | 实现与证据 |
|---|---|
| 仿真位姿抓取 | 从 body/site 读取真值，明确坐标变换、抓取偏置与抓取候选；报告写“真值位姿” |
| 检测后抓取 | 相机图像 → 检测/分割 → 深度或几何定位 → 外参转换 → 规划；保存图像、检测输出、标定、置信度、时间戳和失败重试 |
| 视觉伺服 | 按相机帧率连续观测图像特征或视觉估计位姿，按图像/位姿误差闭环控制；记录延迟、采样保持、误差和饱和 |

视觉算法可用 MuJoCo 真值作**独立评价**，不能偷偷送进控制器替代识别。仿真分割/深度真值属于特殊传感器假设，必须向用户说明并确认；离屏摄像机需要渲染依赖/设备，WebViewer 的浏览器画面不会自动成为 Python 相机观测。

## 接触与载荷

物理抓取需要夹爪驱动、足够夹持力和接触摩擦，验证物体相对末端的滑移、保持与释放。吸附/焊接约束仅作为明确批准的简化；记录开关时刻和反力，不称为真实夹持验证。

不要靠逐帧写关节 qpos 或直接搬动物体实现“成功”。除初始/轮间已批准的复位外，运动经驱动和动力学产生。不得为了通过而移除应有碰撞、改变用户指定质量或加虚假惯量。

每个阶段定义进入条件、动作、退出/成功条件、超时和失败策略。按确认轮数统计成功/失败/重试/未开始的轮次。复位作为事件记录，其非物理跳变不能计入速度/加速度/载荷统计。
